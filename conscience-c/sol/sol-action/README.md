# SOL-Action 0.4.0

Fixed CSV execution with a separate SQL oracle, append-only receipts and exact canonical requirements checked before begin. Every stored requirement must be supported and PASS; otherwise this new path records a bounded refusal and does not call Bridge begin. Result verification and completion re-read source and result. Free-language meaning remains UNKNOWN.

The UI preserves accepted requirements, recovers an original refusal without replay and exports result plus historical proof context without a capability. An independent request after a known refusal starts with new identity and permissions. A historical admission is not a produced result.

The Requirements schema is additive; existing Core, Bridge, Creation and other module APIs are unchanged. Legacy direct paths remain outside this guard. Owner-level PostgreSQL privileges are not WORM isolation. No arbitrary code, model-weight learning, universal error correction or permanent internal memory is claimed.

Runtime release metadata is prepared separately in build-info.json after the code commit. Deployment, current admission and HTTP execution each need their own observed receipts. No deployment success is established merely by this source commit.
